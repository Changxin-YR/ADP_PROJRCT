# ADP 蓝绿发布与生产切换

## 目标

旧版继续运行在 `127.0.0.1:5001`，新版运行在 `127.0.0.1:5002`。两套服务共用同一个生产数据库；迁移前短暂停止旧服务，完成向后兼容迁移和对账后启动新版，再原子切换 Nginx。发布前数据库仅用于可恢复备份，不克隆或切换生产库。

## 发布输入

```bash
bash deploy/deploy-blue-green.sh /root/releases/adp-<版本>.tgz <SHA-256> <版本>
```

版本只允许字母、数字、点、下划线和连字符。脚本拒绝重复版本、错误摘要、迁移校验和漂移、对账差异、健康检查失败或并发发布。

## 自动执行顺序

1. 校验归档 SHA-256，解压到 `/opt/adp/releases/<版本>` 并独立安装 Python 依赖。
2. 构建前端，不改旧站目录。
3. 备份旧代码、旧数据库、Nginx 配置和附件，写入 `/opt/adp/backups/<版本>-blue-green`。
4. 标记维护窗口并停止 `adp-auth.service`，阻断写入。
5. 在同一生产库执行全部迁移、参考字典和只读对账。
6. 启动 `adp-next.service`，在 `5002` 完成健康检查和 50 次有界压力冒烟，再恢复旧服务待切流。
7. 原子替换 Nginx 配置并执行 `nginx -t`、reload、HTTPS 页面及 API 健康检查；失败时恢复旧配置和旧服务。

每次发布的配置、数据库名、摘要、备份目录和对账 JSON 位于 `/var/lib/adp/deployments/<版本>`。环境文件只保存在 `/etc/adp`，不进入归档和 Git。

## 回滚与再次切前

```bash
bash deploy/rollback-blue-green.sh <版本>
bash deploy/deploy-blue-green.sh --activate <版本>
```

回滚只恢复发布前的 Nginx 配置并验证 `5001`，不删除数据库、不删除迁移登记、不停止新版服务。再次切前使用已经验收并留档的新版配置，适合维护窗口内完成“切前、切回、再切前”演练。

## 上线后门禁

必须确认 `/healthz`、`/api/v1/health`、`/api-docs/` 和 `/workbench` 返回正常；生产库对账总差异为 0；旧服务 `5001` 与新服务 `5002` 同时健康；备份摘要可复核；Nginx 当前配置指向 `5002`。任何一项失败时停止发布并恢复旧配置。

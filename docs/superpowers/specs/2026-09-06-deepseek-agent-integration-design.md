# DeepSeek Harness 管理系统融合设计

- 日期：2026-09-06
- 状态：设计已获需求确认，待书面审阅
- 适用项目：ADP 养殖业鱼塘喂养日常管理系统

## 1. 背景与目标

ADP 当前是 Vue 3 + Vite 前端、Flask + MySQL 后端的管理系统。登录由后端通过 HttpOnly `adp_session` Cookie 维护，后端已经承担权限、数据范围、CSRF、幂等和审计职责。DeepSeek Harness 是独立的 TypeScript 插件化智能体运行时，并提供 Python SDK 和 `dsh --profile sdk` 的 stdio JSON-RPC 运行方式。

本次融合的目标是：

1. 在管理系统右下角提供原生智能体入口和对话面板。
2. 让智能体使用当前登录账号的身份、角色、权限和数据范围。
3. 让智能体覆盖现有业务接口，包括查询和在授权范围内的业务操作。
4. 对创建、修改、提交、审核、删除和状态流转等写操作强制人工确认。
5. 权限、角色、账号授权等权限变更始终由人工在管理页面完成，智能体不得修改。
6. 复用现有 Flask service/route，确保智能体不能绕过已有业务规则。

## 2. 范围与非目标

### 2.1 本次范围

- ADP 前端右下角悬浮入口、桌面端侧边面板和移动端底部抽屉。
- ADP Flask 内部 Agent Gateway。
- DeepSeek Harness SDK sidecar 进程及其会话管理。
- 显式、类型化、可审计的 ADP 业务工具目录。
- 会话身份传递、三层权限校验、人工确认、幂等、超时和错误呈现。
- 面向现有业务接口的单元、集成和端到端验收测试。

### 2.2 非目标

- 不嵌入 Harness 自带独立 Web UI。该 UI 使用独立 token/Cookie，且设置 `frame-ancestors 'none'`，不作为 ADP 面板实现。
- Harness 不直接持有原始 `adp_session` Cookie，不直接访问 MySQL。
- 不提供任意 URL、任意 HTTP、任意 SQL、任意 shell 或任意浏览器操作工具。
- 不改变现有角色、权限编码、数据范围模型或人工审批规则。
- 不让智能体自动修改权限、角色、用户授权或其他高风险系统管理配置。

## 3. 推荐架构

采用 `DeepSeek Harness SDK sidecar + ADP 原生 Vue 右下角面板 + Flask Agent Gateway`。

### 3.1 组件职责

**Vue 面板**

- 负责聊天输入、流式消息、工具状态、确认卡片和结果展示。
- 只调用 ADP Agent Gateway，不直接调用 Harness 运行时或业务 API。
- 从当前 ADP 登录状态读取用户体验信息，但不自行判断权限。

**Flask Agent Gateway**

- 是智能体访问 ADP 的唯一业务入口。
- 读取当前 `adp_session`，解析当前用户和数据范围。
- 将白名单工具映射为现有 Flask service/route 调用。
- 在工具执行前和确认执行时重新校验身份、权限、数据范围、版本和业务状态。
- 生成关联 ID、落审计并处理幂等和错误格式。

**DeepSeek Harness SDK sidecar**

- 以受限服务进程运行 Harness SDK，通过 stdio JSON-RPC 驱动 agent。
- 负责模型轮次、工具选择、对话上下文和 Harness 原生 approval 生命周期。
- 只注册 Agent Gateway 提供的工具适配器，不直接加载 ADP 数据库或凭据。
- sidecar 不拥有用户身份；每轮请求都由网关绑定到当前 ADP 会话。

**现有 Flask service/route 与 MySQL**

- 继续作为业务规则、授权、数据范围和事务边界的最终来源。
- 现有校验、状态流转、库存约束、自审禁止、幂等和审计逻辑保持有效。

### 3.2 请求数据流

1. 登录者在 Vue 面板输入自然语言指令。
2. Vue 将消息连同当前会话 Cookie 和 CSRF 头发送到 Agent Gateway。
3. Gateway 从 `adp_session` 得到用户、权限、组织/基地/区域/个人数据范围，并创建 `conversation_id` 和本轮 `request_id`。
4. Gateway 将不含原始 Cookie 的会话上下文和工具目录提供给 Harness sidecar。
5. Harness 选择工具并返回结构化参数；Gateway 校验工具白名单、参数 schema 和请求上下文。
6. 查询工具通过现有 service/route 执行并返回脱敏结果。
7. 写工具先返回待确认操作，Vue 展示确认卡片；用户点击确认后，Gateway 使用一次性确认令牌重新校验并执行。
8. Gateway 返回统一结果和 `trace_id`，Vue 展示成功、拒绝、业务失败或超时状态。
9. 全链路写入现有审计机制，保存用户、工具、参数摘要、确认人、结果和关联 ID。

## 4. 工具目录与业务覆盖

工具必须是显式登记的类型化定义，包含 `name`、用途、输入 schema、输出 schema、风险级别、所需权限、数据范围字段、是否需要确认和对应 service/route。自然语言不得转换为任意 URL 或任意 HTTP 请求。

### 4.1 业务域覆盖

工具目录以现有 Flask 蓝图和 OpenAPI 生成结果为基线，覆盖以下域：

| 业务域 | API 前缀 | 覆盖内容 | 写入策略 |
| --- | --- | --- | --- |
| 认证与当前用户 | `/api/v1/auth` | 当前用户、工作台上下文、会话相关只读信息 | 登录、登出、密码和注册流程保留现有页面/人工流程 |
| 系统管理 | `/api/v1/admin` | 申请、用户、审计日志、角色和选项查询 | 权限/角色/授权修改始终人工；其他写入按风险确认 |
| 基础资料 | `/api/v1/master-data` | 鱼塘及其他主数据查询、创建、更新、提交、审核、归档、状态申请 | 创建/更新/提交/审核/删除/状态流转需确认 |
| 生产 | `/api/v1/production` | 批次、投喂、生产记录、校正、提交、审核、批次状态、对账 | 查询直执行；所有写入和状态流转需确认 |
| 仓储 | `/api/v1/warehouse` | 仓库、出入库、调拨、台账、预警、校正、提交、审核、发货、收货、取消 | 查询直执行；库存和单据写入需确认 |
| 采购 | `/api/v1/purchase` | 订单、退货、应付、付款及提交、审核、冲销 | 查询直执行；单据和资金相关动作需确认 |
| 销售 | `/api/v1/sales` | 订单、交付、退货、应收、收款及提交、审核、冲销 | 查询直执行；单据和资金相关动作需确认 |
| 成本 | `/api/v1/cost` | 成本条目、费用、资产、分摊、结算、净额报告及状态流转 | 报表查询直执行；录入、确认、冲销和规则变更需确认 |
| 数据交换 | `/api/v1/data-exchange` | 模板、导入预览/确认/撤销、导出、附件 | 预览和下载直执行；导入确认、撤销、导出任务需确认 |
| 工作台 | `/api/v1` | 汇总、工作项、通知 | 查询直执行；工作项和通知更新需确认 |

实现时必须从 OpenAPI 和 Flask 路由清单生成覆盖矩阵，逐项标记“已登记工具、人工专属或明确排除原因”。新增业务路由必须通过同一登记机制加入，不能依赖模型自行发现。

### 4.2 风险分类

- **查询类**：列表、详情、汇总、报告、台账、选项和只读审计信息，可直接执行，但仍受当前用户权限和数据范围限制。
- **业务写入类**：创建、修改、校正、导入确认、提交、审核、删除、归档、取消、发货、收货、付款、收款、冲销和状态流转，必须人工确认。
- **人工专属类**：权限、角色、用户授权、账号状态和密码等系统管理变更，智能体只解释当前状态或引导人工页面，不产生修改请求。

## 5. 身份、权限与安全边界

### 5.1 会话绑定

- 浏览器仍使用 HttpOnly `adp_session` Cookie；Vue 不读取或复制 Cookie 值。
- Agent Gateway 与普通 ADP API 使用相同会话和 CSRF 约束。
- Harness sidecar 不保存原始 Cookie、不接收数据库凭据、不持有长期用户 token。
- 会话过期、注销或密码变更导致会话失效时，面板立即停止工具调用并要求重新登录。

### 5.2 三层校验

每一次工具执行都依次经过：

1. **工具层**：工具名称在白名单中，参数符合 schema，风险级别和确认状态匹配。
2. **网关层**：当前会话有效，CSRF/确认令牌有效，用户拥有所需权限，目标对象处于允许的数据范围。
3. **业务层**：现有 Flask service/route 再次执行权限、数据范围、版本、状态、库存、组织关系和业务约束检查。

任一层失败即停止，不让模型自行重试、猜测或改写参数。

### 5.3 人工确认协议

写工具首次调用只生成待确认操作，返回：

- 友好动作名称和目标记录；
- 完整但脱敏的关键参数；
- 预计影响和风险提示；
- 当前用户和所用权限摘要；
- 一次性、短时有效的确认令牌；
- `conversation_id`、`request_id` 和过期时间。

用户点击确认后，Vue 只提交确认令牌和面板会话标识。Gateway 丢弃客户端重新提交的原始参数，使用服务端保存的待确认内容重新校验并执行。取消、过期、重复使用或会话变化均不能执行。

## 6. 右下角面板交互

### 6.1 桌面端

- 默认显示紧凑悬浮入口，固定在右下角，不遮挡主要表格和操作栏。
- 展开为右侧面板，约占桌面宽度 30%，保留当前页面上下文。
- 面板包含消息区、输入区、工具执行状态、待确认卡片、结果摘要和关联 ID 展开区。

### 6.2 移动端

- 入口仍在右下角，但展开后采用底部抽屉。
- 抽屉可拖动/关闭，输入区适配软键盘，确认按钮固定在可触达区域。
- 不改变现有移动端页面路由和人工操作流程。

### 6.3 状态与可访问性

- 未登录、离线、连接中、思考中、待确认、执行中、成功、拒绝、业务失败、超时和会话过期均有明确状态。
- 支持键盘焦点顺序、Esc 关闭、确认按钮可聚焦和基本屏幕阅读器语义。
- 长结果默认摘要展示，可展开查看；敏感字段按现有前端脱敏规则处理。

## 7. 错误处理、幂等与审计

### 7.1 关联 ID

- 每个对话有 `conversation_id`。
- 每个工具调用有 `request_id`。
- Flask 统一响应中的 `request_id` 作为 `trace_id` 对外展示和日志关联。

### 7.2 超时与重试

- Gateway 到 Harness 的单轮默认超时为 30 秒，可配置但有上限。
- 查询超时返回“未完成”并允许用户显式重试。
- 写操作超时不自动重试；先通过状态查询判断是否已落库。
- 数据库锁冲突、服务不可用等沿用现有错误码和人工可理解的提示。

### 7.3 幂等

- 所有写工具携带 `Idempotency-Key`，复用现有 Flask 幂等机制。
- 相同用户、动作和 key 的相同参数返回原结果；参数冲突返回冲突错误。
- 没有幂等支持的接口不得盲目重放，只能在执行前查询状态或要求人工处理。

### 7.4 审计

审计至少包含登录用户、会话标识、工具名、参数摘要、目标对象、风险级别、确认人、执行结果、拒绝原因、耗时和 `conversation_id/request_id/trace_id`。敏感字段脱敏，留存和访问策略沿用现有审计机制。

### 7.5 降级

Harness 或 Agent Gateway 不可用时，主系统人工页面继续工作；右下角面板显示离线状态并不阻塞其他业务请求。任何不确定的模型输出、工具解析失败或权限决策失败都降级为人工处理提示。

## 8. 测试与验收标准

### 8.1 后端与网关

- 每个已登记业务工具至少有成功调用测试，并覆盖 schema 校验和业务错误映射。
- 查询工具可直接执行；写工具在未确认时绝不触发业务接口，确认后才执行。
- 用不同角色、组织、基地、区域和个人数据范围验证越权请求被拒绝。
- 权限、角色、账号授权等操作始终返回人工处理提示，不能产生修改请求。
- 覆盖 CSRF 失败、会话过期、记录版本冲突、非法状态、重复 key、超时和服务不可用。
- 审计字段和脱敏结果完整，关联 ID 在网关响应、日志和审计中一致。

### 8.2 前端面板

- 验证未登录、正常登录、会话过期、离线、网关错误、空结果和长结果。
- 验证桌面悬浮入口、右侧面板、移动端底部抽屉的布局和关闭行为。
- 验证确认卡片信息完整；取消不发请求；确认令牌只能使用一次。
- 验证成功、拒绝、业务失败和超时的展示以及关联 ID 查看。
- 验证键盘操作、焦点顺序、Esc 关闭和基本屏幕阅读器语义。

### 8.3 端到端验收场景

1. “查询鱼塘”：在当前数据范围内返回列表或明确空结果。
2. “创建鱼塘并确认”：先显示确认卡片，确认后创建成功并返回记录。
3. “创建鱼塘但取消”：取消后业务库无新增记录。
4. “越权查看”：返回权限/数据范围拒绝，不泄露记录内容。
5. “重复提交”：同一幂等 key 不产生重复单据。
6. “修改权限”：智能体明确要求人工在管理页面完成，数据库无权限变更。
7. Harness 或网关不可用：主系统人工功能仍可使用。

### 8.4 完成条件

- OpenAPI/路由覆盖矩阵中所有业务接口均已登记工具、标为人工专属或有明确排除依据。
- 后端新增测试、前端测试、构建和必要的 Playwright 验证全部通过。
- 现有人工登录、权限、审批、库存和财务流程回归通过。
- 任何失败场景都不会绕过权限、猜测业务参数或重复写入。

## 9. 实施边界与顺序

实现计划应按以下顺序拆分，并在每个阶段先写失败测试：

1. 建立 Agent Gateway 的会话绑定、统一错误和关联 ID契约。
2. 建立工具注册表和 OpenAPI/路由覆盖矩阵，先接入只读工具。
3. 接入 Harness SDK sidecar 和工具调用桥接。
4. 增加确认令牌、幂等和写工具适配，优先覆盖鱼塘、生产和仓储主流程。
5. 接入采购、销售、成本、数据交换、工作台及其人工专属边界。
6. 开发 Vue 右下角面板和移动端抽屉。
7. 完成安全、异常、回归和端到端验收，最后再开放生产配置。

该顺序不改变业务服务边界；每个工具最终仍调用现有 Flask service/route，并由现有 MySQL 事务完成落库。

# 面试演示指南（AI 全栈 · 核心档）

> 面向 AI 全栈岗：重点不是"我做了个养殖系统"，而是**"我让大模型安全地操作了一套有权限、有状态机、
> 有审计的企业业务系统，并且能力边界由契约自动保证"**。
> 数据前缀 `MT2609-`；配套数据清单 `docs/manual-test/TEST-DATA-CHECKLIST.md`。

## 一、一句话主线

    用户对话 → 智能体读真实业务数据 → 按登录用户的权限直接落地增删改（默认 AGENT_WRITE_MODE=direct）
             → 全程审计 + 请求号 → 业务页面立刻能核验结果
    （需要更保守时把 AGENT_WRITE_MODE 改成 confirm，写操作会回到「弹确认卡片 → 人点头」的老流程）

## 二、五个必须讲清的设计决策

| 决策 | 实现位置 | 为什么这么做 |
| --- | --- | --- |
| **智能体不是"新用户"** | `backend/layers/product/agent/routes.py`：`X-Agent-Context` 是把当前登录会话 token 用 Fernet 加密的一次性委派，TTL 180s | 不引入第二套鉴权/权限体系；数据范围、RBAC 自动继承；多 worker 也能校验（自包含，不依赖进程内缓存） |
| **工具集是封闭的** | `agent_tool_registry.py`：186 个工具全部从 `api-docs/openapi.json` **推导**生成，**没有任何手写映射表** | 新增接口后契约测试会红，必须重新生成 → 能力不可能漂移；模型无法在运行时新增 URL / SQL |
| **写操作可放开、也可收回** | `AGENT_WRITE_MODE`：`direct`（默认）权限校验通过即落地；`confirm` 走 `agent_confirmations` 表（pending + token_hash + TTL 120s + 一次性消费）。两种模式共用同一套权限/数据范围/幂等/审计 | 业务上要「用自然语言直接操作数据」，安全上要能随时退回人工闸门；切换只改环境变量，不改代码 |
| **智能体不能递归调自己** | 工具生成时显式跳过 `/api/v1/agent/` 前缀（5 个端点不在工具集内） | 避免自我递归与权限放大 |
| **每一步都可追溯** | 审计记录 user_id / request_id / tool_name / payload；前端把 request_id 显示在回答下方 | 出问题能按 request_id 定位到具体一次调用 |
| **人在环上只有一个队列** | 写操作确认会同时建一条 work_items 待办（source_key = agent:confirmation:{id}，指派给发起人，状态 claimed），确认后由同一事务外层的收口逻辑置为 completed | 业务侧的核验待办与智能体的确认待办**出现在同一个待办队列**；待办是持久化的，刷新页面也不会丢 |
| **过期与取消都有级联** | 确认到期时 `mark_expired` **返回被处理的确认 ID**，调用方据此把对应待办收口为 cancelled；手动取消同样级联 | 不会留下「永远停在 claimed」的僵尸待办。刻意返回 ID 而不是只改状态：只改状态的话调用方拿不到 ID 就无法级联 —— 这是我第一版真实留下的尾巴 |

## 三、10 分钟动线

### 第 1 幕（2 分钟）架构陈述（不开电脑）

> "这是养殖场的运营系统。系统里每一个写操作都要求双人复核、状态机合法、乐观锁版本一致。
> 我给它接了一个智能体，但我的目标不是让它变聪明，而是**让它变安全**：
> 它只能用登录用户本来就有的权限、只能调用契约里存在的接口、写操作必须有人点头、而且每次调用都留痕。"

### 第 2 幕（3 分钟）读路径：回答是不是真的

先跑数据：

    python -m scripts.manual_test_flow --base-url http://127.0.0.1:5001 `
      --writer-id 写入账号 --writer-password '密码' `
      --verifier-id 核验账号 --verifier-password '密码'

然后在前端（核心档）依次提问，**每次都把回答和页面上的数字对照**：

| 提问 | 立刻打开核验 | 说明 |
| --- | --- | --- |
| `现在有几个塘口，1号塘还剩多少鱼？` | 塘口档案 | 回答来自批次流水汇总（`/production/ponds/{id}/stock-summary`），不是档案里那个手工值 |
| `哪个批次还在养殖中，预计什么时候出塘？` | 养殖批次 | |
| `这个客户还欠我们多少钱？` | 应收账款 | 回答 = 已核验交付生成的应收 − 已核验收款 |
| `最近一次规格抽样是多少？` | 塘口详情 | 只认 **已核验** 的抽样记录 |

> 讲点："它的答案之所以可信，是因为它调的是和页面同一个接口，而不是自己编一张表。这就是我用 OpenAPI 推导工具集的原因。"

### 第 3 幕（3 分钟）写路径：智能体真的把数据改了

默认（`AGENT_WRITE_MODE=direct`）：

| 操作 | 观察什么 |
| --- | --- |
| 对智能体说 `帮我把 1 号塘这批鱼按 450 公斤、单价 17 元记一笔销售` | 回答是「已新增销售单…」这种人话（不带接口名/状态码/JSON），**不是**让你再点一次确认 |
| 打开销售明细 | 单据已经在那里 —— 说明它真的落库了，不是嘴上说说 |
| 点开操作日志 | 这一次调用有审计：操作人、工具、before/after、请求号 |
| 再说 `把这单删掉` | 破坏性操作会先只读核实到唯一对象才执行；说得含糊（「把那些删掉」）它会先反问对象 |
| 换个只有 `production.view` 的账号重试同一句 | 403 —— 智能体的权限永远等于登录者本人 |

需要给评委看"闸门可以随时关回来"时，把 `/etc/adp/next.env` 改成 `AGENT_WRITE_MODE=confirm` 并重启：

| 操作 | 观察什么 |
| --- | --- |
| 重发同一条写指令 | 面板弹出**确认卡片**：中文动作 + 影响对象 + 填写内容 —— 此时**数据库里还没有任何单据** |
| 先打开**我的待办** | 待办队列里出现智能体待确认：…，与业务核验待办同列 |
| 点确认 | 后端用**你的登录身份**重新校验权限/版本/状态机后执行；权限不足 403、状态机不合法 409、缺凭据 400 |
| 再点一次同一个确认 | 一次性消费，二次使用被拒 |
| 让确认卡片放着不管超过 TTL | 下一次对话会把过期确认置为 expired，**对应待办自动变为已取消**（惰性清理，无调度器） |
| 刷新销售明细 | 单据出现，可继续走"换人审批 → 交付 → 应收" |

讲点："放开不是拆护栏：切换只是改一个环境变量，权限、数据范围、幂等、审计四层在两种模式下完全一样。"

### 第 4 幕（2 分钟）权限与审计

| 操作 | 观察什么 |
| --- | --- |
| 用一个只有 `production.view` 的账号提问`应收账款` | 403 或按数据范围过滤 —— **智能体不会替用户越权** |
| 打开系统管理 → 操作日志 | 能看到智能体的每次调用：操作人、request_id、工具、时间；表只追加、无删除入口 |
| 把面板里回答下方的 `request_id` 拿去日志里搜 | 精确命中那一次调用 |

## 四、本地把智能体跑起来

后端需要一个 sidecar 进程（受限配置）：

    # .env（不要提交）
    AGENT_SIDECAR_COMMAND=dsh
    AGENT_SIDECAR_HOME=<可写绝对路径，例如 D:/adp-agent-sidecar>
    AGENT_SIDECAR_CWD=<仓库根目录>
    AGENT_SIDECAR_PATCH=backend/layers/features/agent/agent-restricted.patch.yml
    AGENT_REQUEST_TIMEOUT_SECONDS=90
    AGENT_CONFIRMATION_TTL_SECONDS=120
    # 默认 direct（直接落地）；改 confirm 即回到人工确认闸门
    AGENT_WRITE_MODE=direct

前端：

    cd frontend; npm run dev:demo      # 核心档：只留可核验的数据面 + 全局对话浮层

> 智能体不可用时，面板会自己隐藏（`v-if="available"`），不会挡住演示；此时改走 `docs/manual-test/TEST-DATA-CHECKLIST.md` 的人工闭环。

## 五、如果被问"为什么只有这几个模块"

给结论，不辩解：

> "演示档只保留能当场核验智能体答案的页面：塘口/批次存量、出塘、销售、应收、成本与结算。
> 完整档（`npm run dev`）还有日常投喂、仓间调拨、库存盘点、请购、退货、批量导入导出、角色权限管理。
> 取舍写在 `frontend/src/layers/common/ui/app-shell/demoScope.ts` 的注释里，`frontend/tests/demo-scope.spec.ts` 有断言锁定。"

## 六、诚实边界（被追问时主动说）

- 本机没有 MySQL 凭据，真实唯一键冲突 / 并发 / 备份恢复演练的用例是 skip，需在有库环境跑（`ADP_TEST_MYSQL_ALLOW_DISPOSABLE=1`）。这些用例是写好的，不是没写。
- 默认 `AGENT_WRITE_MODE=direct`：智能体按登录者权限直接落地增删改；改回 `confirm` 时写操作确认会接入统一待办队列（work_items），
  业务核验与智能体确认共用一个入口；但确认与业务核验仍是两个动作：智能体确认只代表允许执行这次工具调用，单据本身的核验仍需按业务规则由他人完成。
- 请购单号与采购单号共用编码空间，撞号时错误文案语义偏"已转换"，属待产品决策项（测试里已标注）。
- 退货接口不返回 `allowed_actions`，前端按状态机推导动作，越权依赖后端 403 兜底。

## 验证维度

| 维度 | 结果 |
| --- | --- |
| 菜单与路由守卫 | 前端 E2E 覆盖权限码路由、无权限入口隐藏和重定向；34 个场景连续两轮通过。 |
| 页面权限 | 每个业务页由明确权限码守卫；无权限用户不能进入受限路由。 |
| 操作权限 | 管理、提交、核验等操作由后端服务再次校验，不依赖前端隐藏。 |
| 管理接口防越权 | 7 个低权限账号对 `/api/v1/admin/users` 的读取与提交均为 403。 |
| 数据范围 | 范围过滤同时校验区域、基地、企业和个人；北区、南区、个人范围均进行了实际查询。 |
| 岗位分离 | 经办人与核验人分离；自审、跨范围写入和无凭证核验均由服务端拒绝。 |

## 人工复核要点

1. 使用任一低权限账号登录后，尝试直接访问 `/admin/users`，应被重定向到工作台或显示无权限，不能显示账号管理数据。
2. 使用 `acceptance_finance` 查询塘口，应能看到默认基地内的验收塘口；查询应付应看到 `ACCEPTANCE-20260901` 关联记录。
3. 使用北区或个人范围账号搜索南区及非本人记录，应返回空列表，不应通过前端筛选绕过服务端。
4. 管理员可在“系统管理 → 用户管理”确认七个 `acceptance_` 账号均为启用状态及相应角色。
